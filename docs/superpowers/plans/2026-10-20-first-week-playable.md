# 首周 D1–D7 实施计划

日期：2026-10-20。状态：2026-10-21 已完成并验收，详见 docs/validation/first-week-playable.md。依据：现行 PRODUCT、首周 80 案内容底稿、终局因果稿，以及 DSH 的只读接口分析。

目标：在保留首日进度和已验证行为的基础上，扩为 80 案首周，结束在 D8 班前待续。人物、剧情和规则选择沿用已确认设定，制作细节由开发实现后校准。

最新试玩修订优先：两模式每天有效值班时间上限均为 60 秒，归零立即收班，不能延办当前案件；部分案件结算合法，未审批不计件、不判错。画布使用与显示尺寸及 DPR 匹配的实际分辨率，640×360 只作逻辑坐标。首周扩展不得恢复旧六分钟、轻松不限时或低分辨率整幅放大的行为。

2026-10-21 后续操作修订覆盖本文旧叠件设计：所有证件都是独立物件，画布内自由摆放；移除册内吸附、绑定与批量退还。翻册和移册不改变附件坐标，先后顺序不限但必须逐件退还。实施与兼容性验证见 docs/validation/independent-papers.md。

## 1. 先冻结共享状态

现有 schema1 是 D1 单册状态，不能直接追加 72 案。先引入 schema2，保持原物理存储键并提供确定性迁移：

- `DayDef`：日号、规则版本、有限案列、当天载体、值班时长、班前场景和收班事件。
- `Paper`：ID、种类、来源、所属案件、坐标、层级、页、实际已交付事实、叠件与退件状态。
- `CaseRuntime`：已问到的句子、已实际交出的材料、补件与裁决。
- `RunStateV2`：当前日、当班状态、统一纸张图、历史裁决、人物事实、账本、夜间状态、家庭、旧规与守卫事件。
- `evaluateCase`：只读取当天规则与已实际提交证据，返回发现与合规判定；UI 不显示答案。
- `ask` 与 `return-stack`：主动问到才交纸；玩家手动叠件、递还，遗漏可补交，不自动收齐。

共享文件 `run.ts`、`session.ts`、`main.ts` 单写者顺序迁移。其他模块在契约冻结后可分工；每个 DSH 写入任务限定文件，合并后主 Agent 跑测试并看前端。

## 2. 迁移验收先于新增工作日

- v1 的报纸、办件、已盖章待退、未扣租夜间、已扣租夜间、家庭、D2 待续、E13 均保留 `runId`、revision、余额、家庭与账目。
- 旧案裁决进入历史，章迹和已退件不重做；D1 工资／租金／供养不重发或重扣。
- D2 待续迁为 D2 报纸；E13 不复活。
- 加载迁移只在内存进行，首次实际动作成功保存后写 schema2。坏记录保留原文，不以新局覆盖。
- 先将 D1 在 v2 下回归到现有结果，再放开 D2。

## 3. 可分工模块

| 模块 | 交付与顺序 |
|---|---|
| 日内容与案卷 | 按日数据文件、报纸、公文、有限案位、固定人物 ID；D2–D7 严格 12 案／日 |
| 证据与规则 | 日期／机关／编号／主体／绑定／连接／商业授权的纯规则；可补与不可补材料区分 |
| 实体材料渲染 | 许可卡、七国护照册、绑定条、连接证明、商业授权等不同形制；前端由主 Agent 看图与实操 |
| 纸张输入 | 层级、翻页、折叠、手动叠还、可取回、载体章区，固定桌面不扩容 |
| 日间状态机 | 新的一天、案件保底、有限案列、当日错误次数重置、正常收班 |
| 夜间与家庭 | 日次稳定交易 ID，个体耐受、损伤、修复与提前一晚的风险预览 |
| 首周叙事 | 回访事实、D7 唯一旧规原件、正常收班后 A01 固定牺牲、D8 待续 |

DSH 使用默认 Flash／max，当前目录执行。只读任务可并行；工具不允许共享 cwd 的多个写入者时，按文件模块顺序派发写入，避免覆盖。

## 4. 按日接入

1. D2：许可机关、申请编号及首尾包含的有效期；主动问话补交。只按无有效材料处理，不能把无效机关直接叫作伪造。
2. D3：七国护照成为裁决载体，核对主体；国籍与当前 IP 分开，俄罗斯护照／法国 IP 可合规。
3. D4：账号绑定与凭条有效期，不按号段地区拒绝；收件回执不等于绑定完成。
4. D5：具体连接矛盾才要求适用佐证；风险提示不是已证实冒名，共享出口有可核查授权。
5. D6：商业授权的使用人、委托主体、范围与日期；个人技术学习不自动变商业用途。
6. D7：综合已生效规则，不加入未来字段。父亲是否能实际交出唯一旧规原件取决于存亡和交付事实。

D2／D4／D6 的班前小场景不占案位、不扣值班时间、不新增工资。固定剧情人物与普通人连续性按首周底稿保底，不引入随机案件覆盖关键内容。

## 5. 收班、家庭与 A01

- 租金20、电力20、Token20的固定费用不变。标准全正确全供养到D7余额0，轻松到D7余额100；这仍须真实整周验证。
- 长期损伤沿主规格个体阈值实现。先写断供、恢复、修复、临界警告、永久死亡与死人无台词的测试，再接前端；不把首日压力演示冒充完整机制。
- 常驻公文和旧规原件不进入申请人退件堆，布局跨日保存。X04 只有实际收到的唯一原件，没有副本或已读备份。
- D7 必须等正常收班，再演出灰衣 W00 固定牺牲。此时无枪、无假救援按钮、无操作失败处罚，不新增家庭费用。
- 过场行号、守卫死亡、工资、旧规、租金各自保存一次，刷新从实际节点继续；夜间后保存到 D8 待续。

## 6. 验收门槛

- 80 个唯一案号，日计数为 8/12/12/12/12/12/12；独立预期表核对规则与补件结果。
- 每日材料门禁：D1 不读未来字段，D2 无护照，之后逐日解锁；章必须盖在当天真正裁决载体。
- 正确与错误证据边界、日期首尾、不可当日补件、共享出口、商业范围均有独立逻辑断言。
- 多张纸可手动叠放和取回；少退一件不叫下一位，常驻文书不被退走。
- v1→v2 真实快照迁移覆盖全部阶段，刷新／存储失败／跨标签不重复执行。
- 两种模式实际走完整周，核对现金流、家庭状态、人物回访、原件、D7 过场及 D8 待续。
- 1280×720、1920×1080 检查长纸阅读、遮挡、章区、叠还与家属终端。所有新增前端由主 Agent 检视实际画面；后端测试不能只依赖 DSH 自报。
