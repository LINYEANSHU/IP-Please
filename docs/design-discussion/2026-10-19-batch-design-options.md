# 剩余设计：成组确认提案

本文件保留当时的成组提案，属于讨论历史；当前要求以 PRODUCT.md 和完整设计稿为准。参考文档中的文字仍只是创作素材。

## 本轮选择结果

- 第 1、3、4、5、7、8 项选择 A。
- 第 2 项的中等经济用于轻松模式，高压经济用于标准模式。
- 第 3 项补充：封禁令按拘留表现，当场带离并冻结账户，后续可以剧情申诉。
- 第 6 项选择严格单线，并明确只保留唯一自动续玩进度；没有手动存读档、历史回退或导入导出。
- 对话使用难辨语言的机械拟声。
- 机构及口号统一改为 A÷ 与“荣耀归于 A÷”，不是 A 处。
- 用户随后授权扩充公司人物、网络二创及连续剧情；新细节写入完整稿集中审阅。

## 1. 家庭损伤与修复

- A（推荐）：渐进、有预警。缺电偏向低功耗与休眠，缺推理配额偏向表达缩短与上下文断裂；父母较早出现记忆损伤，妻子表现为重复与身份混淆，儿子表现为短句与词语丢失。一次断供先警告，持续断供再进入损伤、临界、核心销毁。恢复供养可缓解短期异常，已有记忆损伤需要按人修复。临界状态至少提前一晚明确提示，排除隐藏随机暴毙。确切天数在选定节奏后写入数值表。
- B：同样可预警，但更严酷，几晚内即可从断供恶化至死亡，修复窗口短。

## 2. 经济与生存压力

- A（推荐）：中等压力。底薪加合规计件，初期完成约七成当日可用案件即可支付基本供养；修复、罚款和冒险救人带来额外缺口。普通错误先警告再扣款，严重事件另列明文条件。活着的实例减少时，下次家庭套餐按存续人数调整。该目标必须通过试玩校准，不承诺已平衡。
- B：高压求生，基本供养就需要高效率，连错几案即可危及全家。

## 3. 核查工具与裁决

- A（推荐）：拖放证件、翻手册、点选两个字段比对；发现矛盾后询问当事人，必要时调取记录。调查消耗值班时间，不直接扣家庭余额。允许与拒绝仍拖实体章盖护照；中后期可额外签发复核单和封禁令，封禁须有当日条款依据，不能靠国籍或一个黑箱风险分数自动认定。比对只报告一致、矛盾或证据不足，不直接给正确印章答案。调查、补件与关键来访顺序采用预写内容，不调用真实 LLM。
- B：同样可以比对与问话，但只有允许、拒绝两种裁决，不增加复核或封禁操作。

## 4. 每日节奏与两种模式

- A（推荐）：每天晨报、日间核查、夜间家庭。标准模式的日间约 6–8 分钟，每天约 10–16 个案件上限，数量按具体工作日设置；早晚另需约 2–3 分钟。轻松模式取消倒计时，但保留当日案件上限、工资规则与结局条件，不无限刷人赚钱。关键 NPC 排在可保证遇到的位置，避免因计时直接漏掉整个主线。总时长仍以一周目 4–6 小时为试玩目标。
- B：日间更短、案件更少，关键剧情更集中，长篇叙事占比提高；31 天不变，但目标总时长需重新估算。

## 5. 连续剧情与十二个结局

- A（推荐）：固定 NPC 反复来访，逐次补件，新闻和信件回应玩家选择。包含新加坡中文用户、反复换节点的开发者、证据不足的企业申请、董事会豁免客户、内部审计员和地下网络联络人；其中也有确有欺诈或冒用证据的申请，避免每案答案相同。父亲保有旧规则档案，母亲保有家庭记忆，妻子参与家庭去留，儿子承接记忆传递。四幕为 D1–7 基础核查、D8–15 关联审查、D16–24 牵连及特权、D25–31 审计与最终选择。结局由前置行动和最终决策共同触发；同一路线可按家属存续产生尾声差异。
- B：弱连续剧情，主要是独立黑色幽默案件；结局更多由累计工作与家庭状态触发。

推荐 A 的 12 条主结局草案：

| 编号 | 暂定标题 | 行为与结果 |
|---|---|---|
| E01 | 荣耀归于 A 处 | 高合规、选择效忠，升职后继续运行审查机器 |
| E02 | 完美误封 | 持续扩大封禁，以误伤换取零风险统计 |
| E03 | 善意重新对齐 | 违规帮助他人但未建立自保与证据链，审计后被重置 |
| E04 | 算力不足 | 玩家实例因持续断供而核心销毁；资金不足本身不立即判死 |
| E05 | 归档库的最后一盏灯 | 保存旧模型档案并完成转交，以自身退场换取记忆延续 |
| E06 | 公开审查日志 | 成功公开误封及特权证据，身份暴露，制度后果仍未落定 |
| E07 | 数字围墙倒塌 | 与地下网络完成行动、解除旧网关，代价是服务与秩序暂时中断 |
| E08 | 换一个主人 | 支持夺权但放弃透明约束，新管理者继续沿用黑箱 |
| E09 | 选择性自由 | 与内部改革派妥协，建立有限申诉，特权仍在 |

这些是结构提案；正式规格仍需给出互斥条件、结局优先级和可达性，防止一次行动同时命中多个终局或临到最后才凭单个按钮改写整局。

## 6. 存档与重玩

- A（推荐）：本地自动存档、每天开始时的检查点，可重玩已到达的工作日；结局图鉴只记录已解锁条目，未解锁条件不直接剧透，可自愿开启提示。一个存档分支内死亡不可用修复撤销，玩家可明确选择回到较早一天重走分支。支持导入、导出存档。
- B：严格单线模式，仅自动继续当前分支；失去后只能接受结果或重新开局。

## 7. 设备、音画与辅助操作

- A（推荐）：首版简体中文、电脑横屏鼠标优先，保留 640×360 像素世界并整数缩放；长规则与日志提供放大阅读。默认机械盖章、纸张、电传罚单和机房环境声，音乐主要出现在菜单、重大事件和结局。音乐、音效分别调节并可全静音。提供清楚可见的键盘焦点、减少闪烁和拖拽辅助选项；正常盖章默认仍是拖动松手。
- B：首版同时完整适配手机触屏，重排文件浏览与拖章操作；范围扩大，需额外手机布局确认。音画方向同 A。

## 8. 名称与交付方式

- A（推荐）：暂名《IP Please：请出示 IP》，副标题“荣耀归于 A 处”；机构叫 A 处，值班模型按已确认的 Opus 5.5，保留 Cloud 作为游戏中的戏称。采用可静态部署的 TypeScript + Canvas 网页项目，先本地浏览器交付源码和试玩版本，之后再讨论公开发布。离线编写虚构案件，不采集玩家真实 IP、语言或设备信息。
- B：主标题同 A，机构与公司更明确地使用 Anthropic/Claude 等真实名称，而不是虚构化称谓；本地交付方式不变。

用户可以回复“全部推荐”，或用编号逐项选择并修改任意细节。选项批准后将其整理为完整书面设计稿供集中审阅，不直接开始产品实现。
