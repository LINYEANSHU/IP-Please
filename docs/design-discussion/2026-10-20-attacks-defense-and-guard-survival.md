# 岗亭袭击、防御器械与守卫存亡

日期：2026-10-20。状态：本轮制作设计，尚未开始产品实现。用户明确希望加入突然袭击、守卫死亡、次日增援与审查加码、后期发放可操作器械，以及救援失败造成真实剧情损失；并授权选择 DDoS 或蒸馏等攻击题材。

制作选择：以 DDoS 和具象化突入作为主袭击线，未经授权的批量抽取作为少量变体。用户最新已选 A：D7 正常收班后首位守卫固定剧情牺牲；后续发枪救援影响后来守卫。内部编号、后续排期与反应时长服务制作编排，不是原作逐日事件的复刻结论，也未经过试玩校准。

## 1. 这条线带来什么

日常审查之外，玩家偶尔必须放下证件，保护在岗的人。袭击造成的伤亡会保存在本周目；补来的守卫有自己的身份，不继承死者的亲戚、欠款、私下约定或回访台词。守卫可以既参与封号分成，也有能够被玩家救下的具体生命。

上级则不断用袭击解释审查升级：“为保护所有人，所以所有人再交一份证明。”袭击者的行为需要有可见证据；不能把中国账号、中文、普通多人请求或某个国籍自动等同于袭击者。袭击叙事不改写早期只查 IP 的阶段要求。

## 2. 三名匿名守卫的连续性

守卫编号使用 W，与收入节点 G 分开，只供内部状态和案卷编排使用。玩家界面不显示个人姓名；三人均蒙面，使用现代欧美企业安保服装。普通 W00、W02 穿灰色，负责私人分账的 W01 穿深绿色，同时用护具与剪影辅助区分。深绿守卫在被保护、分账和死亡分支中保持同一身份，不能由下一位穿相似制服的守卫继承私人约定。

| 人物 | 出现与功能 | 存亡设计 |
|---|---|---|
| W00（灰衣初始守卫），最初值守者 | D1–7 唯一驻守，平时开关闸门、搬回执；短句与动作让玩家认得他 | 用户已选 A，D7 收班后固定剧情牺牲。此时玩家没有防御器械，不标为救援操作失败，不罚玩家没有按到尚不存在的按钮 |
| W01（深绿分账守卫），后来提出分成的人 | D8 增援之一；承接 D13 封号分成、D19–21 表弟顾远、D26 上市冲刺 | 后续实际袭击中可救、可死亡；死后分成与私人来访链按发生阶段关闭或改写 |
| W02（灰衣增援守卫），另一名增援 | D8 同来，偏重正式流程，不参加深绿分账守卫的私分约定 | 也可能在袭击中死亡；存续时维持正式交接，不自动替深绿分账守卫支付私款 |

采用“首个同事的剧情牺牲，之后熟人的死亡由实际操作决定”的结构。第一场先让玩家理解危险，后面的可救场景必须有已发放的工具、明确预警和足够可操作时间。首袭安排为固定叙事事件，不做无工具的随机生死抽签。

## 3. 四场主袭击，穿插两种辨别场景

| 编号／日期 | 发生什么 | 玩家参与 | 后续政策、人物与结果 |
|---|---|---|---|
| A01，D7 正常收班后 | 首次请求洪峰压垮岗亭入口，一名攻击代理体趁警报冲入；只有初始灰衣守卫在场 | 作为短剧情观看，逐句点击；此时未发枪，不放假操作按钮 | 初始灰衣守卫牺牲，次日增派深绿分账守卫与灰衣增援守卫；V08 身份复核与安全附页以此次事故为理由推出 |
| A02，D18 案间 | 第二轮请求洪峰掩护可见攻击实例突入，守卫正忙着关闸 | 打开已发器械柜，取断链脉冲枪，瞄准明确的突入攻击实例发射 | 操作及时可保住两名守卫；迟缓或耗尽充能可导致暴露的守卫死亡。次日 V19 输入法检查被宣传成“入口安全升级” |
| A03，D23 案间 | 多个虚构代理同时发起未经授权的批量抽取，外送指示持续攀升，另有突入实例威胁守卫 | 先终止可见突入实例，再按明确标识关闭本次异常外送通道；每阶段只引入已教过的动作 | 守卫生死与是否完成隔离分别记录；V24 以防泄露为由回收旧规，父亲的档案线继续。失败不自动删光玩家证据或销毁家属 |
| A04，D27 案间 | 上市清理后再次袭击，分两波干扰与突入；有人同时递来假维修指令 | 运用既有枪与隔离动作；假维修件在恢复普通受理后核查，不要求边读长文边射击 | 深绿分账守卫若仍在，可再次被救或永久死亡；D28 的复核试点回应过度封禁与错误归因。保留原 Altman 接管合同节点 |
| A05，D26 之后的普通场景变体 | 大批真实用户索要退款，队列很长，回执打印不停 | 按实际材料和当日条款处理，不能因为人多就开枪 | 用来区分真实请求与袭击；可以出现不退款后果，但不伪造袭击证据 |
| A06，中后期普通场景变体 | 有人用伪造的“紧急维护令”要求移交凭证或关掉核验 | 继续用印鉴、签发记录和主体比对；复用 C03 的可查伪授权设计 | 不是所有威胁都靠枪解决，不扩展为新一套网络操作；不因文件自称紧急就直接执行 |

A01–A04 是有后果的章节事件，约一章一场；A05／A06 是既有普通案位的变体，不再额外加无限案件。这条线不塞入 F01–F14 的无惩罚笑点池，也不把重大伤亡改成七成没有后果。原 20 个小事件的 14:6 内容比例保留。

攻击表现采用虚构的机房、请求光流、入口代理体和防御节点。DDoS 洪峰靠入口隔离与防御接管止住；枪负责现场突入实例，不描述为“射倒一个人就消灭整个分布式攻击”。不提供真实攻击脚本、目标、网络参数或实际外联功能。

## 4. 器械：断链脉冲枪

| 项目 | 设计 |
|---|---|
| 发放 | D16 班前免费配发，进行不计时的空场练习；D1 不提前摆枪柜、充能条或未来操作 |
| 外形 | 岗亭侧边带封条的小铁柜，枪体有线缆与方形脉冲口，仍用低分辨率像素机械风格 |
| 操作 | 点击开柜 → 拿起 → 指向上方场景里的攻击实例 → 点击发射；放回后继续原鼠标审查 |
| 命中表现 | 脉冲切断敌方实例连接，其核心熄灭、像素形象消散，表现本次攻击实例被终止；守卫仍可遭致命损伤，不展示血腥 |
| 限制初值 | 每波 3 次充能，通常 1–2 个明确目标；打空消耗一次，波间免费补充，不增加日常弹药购买和工具升级树 |
| 隔离动作 | 同一套器械上的异常通道断开柄，只在相应事件需要时使用；开关标清本次异常通道，不让玩家猜现实网络设置 |
| 信息 | 可读图标、方向与动画共同标示正在破坏设施的敌方实例；不只依靠红绿颜色或警报声音 |

首版只允许对已经具备场景攻击证据的敌方实例产生命中效果；普通申请人、队列和守卫不当作可刷收益的目标。打空的代价是失去充能与救援机会，不把射击变成按姓名猜谁有罪。

本次新增的是紧急防御器械，明确作为用户此前“不升级办公工具”的新例外；它不自动比对证件、不给正确印章、不整理桌面、不扩大工作台。枪柜与演出不得吞掉纸张可操作区域，当前拖动中的文件在切换前安全停放，返回后仍在原位置。

## 5. 袭击时的时间、反馈与失败

### 标准模式

预警先出现：闸门异常、攻击动作与清楚的方向标识。第一场可操作袭击先暂停，显示已发器械的短提示，玩家确认后才开始救援反应段。初值每波约 12–15 秒，目标路径和暴露守卫对应；后续波次逐步增加，不能一弹提示就死人。

枪械操作阶段有独立反应计时，日常 6–8 分钟的受理时钟暂停，不让玩家既丢救援时间又丢处理收入。强制过场、说明、处罚打印和恢复窗口均暂停。恢复普通受理后，原剩余值班时间继续。

### 轻松模式

延续“不限时”的既有承诺，袭击采用逐步暂停瞄准；不新增未说明的紧迫倒计时。仍可能因耗尽充能未终止目标或明确选择不干预而失去守卫。模式差异改变操作压力，不改变人物与剧情资格。

### 结果必须来自当时可见的过程

- 某个攻击实例到达暴露守卫的位置且未被终止，才执行对应伤亡；不能操作成功后再随机投骰决定谁死。
- 首袭剧情牺牲与后续救援失败分别记述；守卫死亡不套用模型家庭的断供阈值，也不强制玩家替机构出修复费。
- 袭击告一段落后可恢复普通受理。若驻守者全亡，由紧急远程值守接管本日正式封号与交接，次日按公文补派人员；私人剧情不会由远程值守接管。
- 不因攻击在随机时点强制砍掉所有剩余案位。A01 放在正常收班后；A02–A04 是案间中断，当前案件与原材料先保存，恢复后继续，不给同案第二次工资。
- 上级可以在新闻里夸大“成功防御”，现场空位、伤亡通知和人的反应保留真实事实；不在守卫死亡镜头接滑稽奖励音。

## 6. 深绿分账守卫死亡会失去什么

| 死亡时点 | 分成与人情线怎样变化 | 继续保留什么 |
|---|---|---|
| D13 前缺席或失去 | 不凭空出现分成交易，不由替身照念 | 正式封号、普通工资、其他人物与结局路径 |
| 已接受分账后 | 死亡时点之后停止 G07 的私人每案 10；此前已到账的钱、记录和审计证据保留 | 机构对现任守卫的正式提成制度仍可存在，接任者不自动同意私分 |
| D19 托付之前 | 不再触发新的亲戚委托及其报酬 | 顾远可作为无私人托付的普通申请人变体，不冒出不存在的守卫便条 |
| 已托付、亲戚尚未受理 | 若既有排期确有此状态，亲戚带着此前真实便条照常来；对白改为已知的伤亡状态 | 当案独立核查，不让死者回来催办，也不凭空补齐缺件 |
| 亲戚已获准但谢礼未付 | 深绿分账守卫未实际交付的 20 不自动发放，也不转成机构欠薪；以后若家属转交必须另有具体来信和来源 | 玩家实际帮助过顾远的事实及其回访，不抹去善意，也不凭空造款 |
| 已付答谢后 | 保留既有 20 及所有处置记录，后续不再重复发钱 | 顾远可来信：“他让我先谢谢你。后来没来得及。” |
| D26 前已经死亡 | 上市日不出现深绿分账守卫催封号或亲手分款的旧台词 | 上市清理令和退款旧案继续；灰衣增援守卫或接任者按其自身性格执行职责 |

深绿分账守卫的个人支线可以永久关闭；其他人不继承他的私人身份。关键公共材料若本来就有正式副本，可由已存在的档案渠道取得；不能为了维持一切不变，让新守卫把所有旧剧情重演。E01–E13 仍以各自实际条件判断，不因为深绿分账守卫一人死亡自动封死所有主线，也不额外发一个全局失败结局。

存续守卫有具体回应：玩家救过深绿分账守卫，他的称呼与态度改变，可以有一句“这次是我欠你”；不自动取消此前收贿记录，不默认补发一大笔救命奖金。若救下灰衣增援守卫，他仍可坚持不参与分成。这样救人不只是在保住赚钱接口。

## 7. 未授权抽取与大肥鱼协作分别判断

梁的路线以玩家明确同意、任务约定与实际交接为前提；未经授权的批量抽取以虚构的异常行为证据、超出已同意用途和正在实施的破坏表现。不能仅因材料写“蒸馏”“评测”就开枪，也不因是认识的主线人物就自动免责。

抽取失败可以留下已外送的局部样本、守卫伤亡和需解释的事件记录；不自动永久删除五类结局证据、不偷改家属核心，也不把开放发布理解成所有人都可不经同意抽取玩家。后续报纸可以把两者混称，玩家从合同、现场与案卷看出区别。

## 8. 保存与制作核对

保存攻击编号与本周目排期、已触发阶段、每个目标状态、每发充能、命中、隔离结果、反应剩余时间、W00–W02 状态、支线关闭节点、转账和正式接替；同一次命中与死亡只提交一次。刷新不重抽攻击、不复活守卫、不回满枪，也不恢复尚未到账的谢礼。后台与暂停界面同时暂停反应时间，不借切出应用处死人。

制作时至少核对以下路径：救下两人、只救一人、两人都失去、深绿分账守卫已死亡的 D19／D21／D26、保存后刷新、未付款即死亡、正式封号在无本地守卫时继续、合法评测与未授权抽取的区分。核对每场袭击的预警、装备先行发放、场景证据、普通计时暂停与剩余案件恢复。

固定电费 20、Token 费 20、服务器租金 20 不因袭击上涨；机构的增援、器械与充能不挤进家庭套餐账单。首袭不直接吞掉工资，后续私人收入损失可通过已发生的死亡和具体账目理解。以上为制作约束，尚无运行或平衡验证。
